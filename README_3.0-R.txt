하루 3.0-R — 기존 일정 수정·삭제 안전성 시험판
기준: 3.0-Q. 기존 localStorage 키 및 겨울 UI 보존.

1. AI 판단에 update/delete와 targetId 추가. 기존 일정 변경은 신규 등록으로 처리하지 않도록 안내.
2. 수정/삭제 전 기존 id 재확인, 확인창에서만 실제 데이터 변경.
3. 변경 후 로컬 저장소에서 해당 id의 수정/삭제 결과를 검증한 뒤 완료 메시지 표시.
4. 대화 기록과 실제 저장 목록을 압축하여 AI 요청 본문 크기 감소. HTTP 오류 시 서버 응답 앞부분을 개발자 콘솔에 기록.

검증: 전체 JS 문법 검사, 소스 정적 검증 완료. 실제 AI 서버의 HTTP 400 원인과 실기기 동작은 이 환경에서 검증하지 못함.
주의: 같은 날짜에 동일 제목 일정이 복수인 경우 AI가 targetId를 정확히 지정해야 함. 모호하면 확인을 요청하도록 프롬프트 설정. 설치 전 데이터 백업 권장.
